# ChisKit 0.1b / GB compare 208 真机测试

本版只优化 GB/GBC ROM 写入后的最终校验：每次提交最多 16 KiB，
由独立 FPGA 字节比较器直接比较卡带 NOR 与 PSRAM；ROM 之外的 NOR 尾部检查 FF。
不再将该校验的数据搬进 SDRAM。Mapper bank 仍由 OS 在两次任务之间切换。

GBA 比较引擎、GB/GBA 存档算法、RTC、UI 和公开版本号保持原样。
旧 FPGA 不支持此能力时保留原来的软件校验回退。
16 KiB 是任务长度，不是 NOR 编程缓冲区大小；烧写块大小没有改变。

## 测试顺序

1. 安全退出 USB 模式后重新启动核心。先确认语言、主题、文件选择正常。
2. 使用已经备份且允许覆盖的 MBC5 塞尔达烧录卡，分析卡带，选择已验证 ROM，执行写入。
   最终阶段应显示 `Whole-NOR compare / hardware`，记录速度及最终 `PASS / rc 0`。
   ROM 小于 NOR 容量时仍校验完整 NOR，包括 FF 尾部。
3. 同样测试 MBC3/MBC30 水晶烧录卡。完成后实际启动游戏确认 ROM。
4. 可在最终校验阶段按 B 取消；回到主页后重置、重新分析，确认仍能备份 ROM。
   不要求在擦除或编程中取消，也不要在操作中拔卡。
5. 用已备份的 GBA 烧录卡回归一次 ROM 写入和最终校验，确认原通路没有回退。

不需要重测所有存档写入。可各做一次 GB/GBA 卡带分析、存档备份和 RTC 读取作为轻量回归。
如果出错，保存截图并挂载 USB；不要反复擦写。请提供卡带、阶段、rc 和速度。

## 安装与回滚

SD_ROOT 合并到 TF 根目录。本包更新 app、OS 和 FPGA 三个文件，必须配套更新。
不覆盖 Saves 或设置。自动部署会先保存这三个旧文件，再逐个 SHA256 回读核验。
内部版本为 208；界面继续显示用户指定的公开版本 0.1b。

功能仿真、时序报告、资源数和部署记录见仓库 `docs/GB_COMPARE208_VALIDATION.md`。
仿真不代替真机验证；不预先承诺速度。
